📱 Prima Implementazione — App di Navigazione

Questo documento descrive tutte le funzionalità implementate nell'app di navigazione e il flusso generale di interazione per l'utente.

1. Panoramica delle Funzionalità

L'app di navigazione offre cinque macro-funzionalità integrate:

# Funzionalità Descrizione
TASK 1 Ricerca con Places Autocomplete Ricerca testuale con suggerimenti in tempo reale, debounce e session token per ottimizzazione costi
TASK 2 Flusso ricerca testuale Flusso completo: digitazione → suggerimenti → selezione → coordinate
TASK 3 Selezione punto sulla mappa Tap diretto sulla mappa per selezionare una destinazione (POI o punto generico)
TASK 4 Calcolo percorso con alternative Calcolo percorso da posizione GPS con percorsi alternativi, selezione del più veloce
TASK 5 Monitoraggio e ricalcolo Controllo continuo posizione ogni 2s, switch su alternativo o ricalcolo API se deviazione

3. TASK 1 — Ricerca con Places Autocomplete

3.1 Session Token

Il session token è un identificatore univoco (UUID v4) che raggruppa tutte le richieste di una singola sessione di ricerca.

Ciclo di vita del token:
1. L'utente inizia a digitare → genera un nuovo token
2. Ogni richiesta Autocomplete usa lo stesso token
3. L'utente seleziona un risultato → Places Details usa lo stesso token
4. Dopo la selezione → token invalidato, ne viene generato uno nuovo
⚠️ Perché è importante: Senza session token, Google fattura ogni singola richiesta Autocomplete separatamente. Con il token, tutte le Autocomplete + la Details vengono raggruppate in un'unica sessione fatturabile, riducendo drasticamente i costi.

3.2 Debounce (300ms)

Non viene inviata una richiesta per ogni carattere digitato. Un timer di 300ms si avvia dopo ogni battitura:

  • Se l'utente digita un altro carattere prima dei 300ms → il timer viene annullato e ricreato
  • Se l'utente smette di digitare per 300ms → la richiesta viene inviata

Risultato: digitando "Duomo di Milano" velocemente, vengono inviate ~2-3 richieste invece di 15.

3.3 Minimo 3 Caratteri

Nessuna richiesta API viene inviata se il testo digitato ha meno di 3 caratteri. Sotto questa soglia i risultati sarebbero troppo generici e sprecherebbero chiamate API senza beneficio per l'utente.

4. TASK 2 — Flusso Ricerca Testuale Completo

1 L'utente digita nella barra di ricerca
↓
2 Se input.length < 3 → nessuna richiesta (lista vuota)
↓
3 Se input.length ≥ 3 → attende il debounce (300ms)
↓
4 Chiama Places Autocomplete API con il session token
↓
5 Mostra la lista di suggerimenti sotto il campo di testo
↓
6 L'utente seleziona un suggerimento
↓
7 Chiama Places Details API con lo stesso session token → ottiene coordinate (lat/lng)
↓
8 Termina la sessione → genera un nuovo session token
↓
9 Passa le coordinate al calcolo percorso (TASK 4)

5. TASK 3 — Selezione Punto sulla Mappa

Caso 1 — Tap su un POI (negozio, ristorante, luogo registrato)

Se l'utente tocca un POI riconosciuto da Google Maps, la mappa restituisce le coordinate del POI. Le coordinate vengono usate direttamente per calcolare il percorso, senza chiamate API aggiuntive.

Caso 2 — Tap su un punto generico

Se l'utente tocca un punto qualsiasi della mappa che non è un POI:

  • Le coordinate lat/lng vengono ottenute direttamente dall'evento tap
  • Nessuna chiamata a Places Details API (le coordinate sono sufficienti)
  • Il campo di testo della destinazione mostra le coordinate selezionate
  • Si procede direttamente al calcolo del percorso (TASK 4)
Ottimizzazione: Per i punti generici non viene chiamata nessuna API aggiuntiva. Le coordinate lat/lng sono sufficienti per la Directions API.

6. TASK 4 — Calcolo del Percorso

Dopo aver ottenuto la destinazione (da ricerca testuale o da selezione mappa), il sistema:

1 Ottiene la posizione GPS corrente del dispositivo (usata come origine)
↓
2 Chiama la Directions API con alternatives: true
↓
3 Riceve tutti i percorsi (principale + alternativi)
↓
4 Confronta la durata di ogni percorso e seleziona il più veloce
↓
5 Salva tutti i percorsi con le polyline decodificate in memoria
↓
6 Disegna la polyline del percorso attivo sulla mappa
↓
7 Mostra le indicazioni stradali passo-passo nella lista
Modelli dati:
  • RouteData — un singolo percorso (polyline decodificata, durata in secondi, steps, distanza)
  • AllRoutesResult — risultato completo (bestRoute + lista di tutti i percorsi alternativi)

7. TASK 5 — Monitoraggio Posizione e Ricalcolo Automatico

Una volta avviata la navigazione, il sistema esegue un controllo automatico ogni 2 secondi:

Step 2a — L'utente è sul percorso?

Confronta la posizione GPS corrente con la polyline del percorso attivo. Se la distanza minima dalla polyline è ≤ 40 metri, l'utente è considerato "sul percorso" → nessuna azione.

Step 2b — È su un percorso alternativo?

Se l'utente è a più di 40m dal percorso attivo, il sistema verifica se la posizione corrente è entro 40m dalla polyline di uno dei percorsi alternativi salvati in memoria:

  • Se sì: il percorso alternativo diventa il nuovo percorso attivo. Nessuna chiamata API — lo switch è istantaneo.
  • Se no: passa allo Step 2c.

Step 2c — Ricalcolo via API

Se nessun percorso alternativo è compatibile, il sistema:

  • Usa la posizione GPS corrente come nuova origine
  • Mantiene la stessa destinazione finale
  • Chiama la Directions API con alternatives: true
  • Aggiorna il percorso attivo e tutti gli alternativi
  • Aggiorna la mappa e le indicazioni
⚠️ Anti-flood: Un flag _isRerouting impedisce che vengano inviate chiamate API concorrenti. Se un ricalcolo è già in corso, i tick successivi del timer vengono ignorati fino al completamento.

8. Flusso Generale di Interazione

Il flusso completo dell'app, dalla selezione della destinazione alla navigazione attiva, si sviluppa così:

Fase Azione Utente Comportamento App
Ingresso Apre l'app Mostra mappa centrata sull'Italia, avvia GPS
Destinazione (testo) Digita un indirizzo Debounce 300ms → Autocomplete → dropdown suggerimenti
Destinazione (mappa) Tocca un punto sulla mappa Prende coordinate direttamente, nessuna API aggiuntiva
Selezione Sceglie suggerimento / conferma punto Places Details → coordinate → calcolo percorso
Percorso — Directions API, seleziona più veloce, disegna polyline
Navigazione Segue il percorso Monitoraggio ogni 2s, overlay con indicazioni
Deviazione Prende una strada diversa Switch su alternativo o ricalcolo API automatico
